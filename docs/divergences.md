# Deliberate divergences from upstream

Each entry: what differs, why, and the test that pins the divergent behaviour.

| tool      | divergence                                                                                         | reason                                  | pinned by                          |
| --------- | -------------------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------- |
| rinitdb   | Bad-option error text is usage-rs's (clap-shaped) and exit status is 2, not glibc getopt's and 1. | ADR-0004: all CLIs on usage-rs           | `crates/rinitdb/tests/t_001_initdb.rs::program_options_handling_ok` |
| rinitdb   | Long-option unique-prefix abbreviation (`--no-syn` for `--no-sync`) is rejected.                   | usage-rs has no getopt abbreviation      | `crates/rinitdb/src/cli.rs` unit test `abbreviation_is_rejected` |
| gate      | A gate compares the two outputs after three named normalizations (`Time: …` line, `PID n`, system identifier), not as raw bytes. | Each value is nondeterministic per run or per cluster; each normalizer cites the upstream `printf` it rewrites and nothing else is normalized. | `crates/testkit/src/normalize.rs` unit tests (`timing_*`, `pid_*`, `system_identifier_*`) plus `gate::tests::a_normalizer_does_not_hide_a_real_difference_on_the_same_line` |
| gate      | A failing gate renders its `diff -U3` in process instead of shelling out to diff(1) as pg_regress does (`src/test/regress/pg_regress.c:1537`). | Diagnostics only — the pass/fail verdict is a byte comparison, never the rendering — and it keeps the gates free of an external diff(1). | `crates/testkit/src/diff.rs` unit tests (`a_changed_line_is_shown_with_three_lines_of_context`, `a_missing_final_newline_is_flagged`) |
| testkit   | `command_like` / `command_fails_like` match a subset of Perl regex implemented in `testkit::pattern`, not Perl itself: flags move from a trailing `/ms` to a leading `(?ms)`, `\d`/`\w`/`\s` are ASCII, and backreferences, lookaround, `\b` and `/x` are compile errors rather than matches. | The `regex` crate is not approved (AGENTS.md, "stdlib first") and substring matching would silently weaken every stolen `qr//`. `^`/`$` keep Perl's semantics, including `$` before a trailing newline, so the patterns themselves are copied verbatim. | `crates/testkit/src/pattern.rs` unit tests (`anchors_follow_perl_not_rust`, `a_trailing_anchor_after_a_number`, `unsupported_constructs_are_errors_not_silent_mismatches`) |
| testkit   | `check_mode_recursive` returns the list of offending entries instead of a bool, its message appends the mode actually found, and an entry that is neither a file nor a directory is a returned violation instead of `die`. | Upstream prints each bad entry to stderr and returns 1/0; returning the list keeps the calculation pure, reports every entry at once and lets `check_mode_recursive_ok` do the panicking. The wording is otherwise upstream's `"$name mode must be %04o"`. | `crates/testkit/src/files.rs` unit tests (`a_directory_is_judged_by_the_directory_mode`, `an_unknown_file_type_is_a_violation`) |
| rinitdb | The effective user (`get_id()`, `initdb.c:817`) comes from `USER`/`LOGNAME`, not from `geteuid()` + `getpwuid()`. | Neither call is reachable from the standard library; the crate is `#![deny(unsafe_code)]` and no libc dependency is approved (AGENTS.md). It only matters when `--username` is absent, and it is checked against the `pg_` rule exactly as C checks the real one. | `crates/rinitdb/src/validate.rs` unit test `the_effective_user_is_the_default_superuser_name_and_is_checked_too` |
| rinitdb | `--locale` always wins over `--no-locale`; C's getopt applies whichever came last on the command line. | usage-rs reports which flags were given, not where; upstream's own tests never combine the two. | `crates/rinitdb/src/validate.rs` unit test `an_explicit_locale_wins_over_no_locale_whatever_the_order` |
| rinitdb | When a command line carries two errors from the getopt loop (`-c NAME` with no `=`, and an unrecognized `--locale-provider`), the `-c` one is always reported; C reports whichever option came first. | Same cause: the parser hands over fields, not positions. Each message on its own is upstream's. | `crates/rinitdb/src/validate.rs` unit test `two_getopt_stage_errors_are_reported_in_a_fixed_order` |
| rinitdb | Paths appear as they were typed — in error messages, and as the target of the `$PGDATA/pg_wal` symlink; C runs `canonicalize_path()` (`initdb.c:2646`, `:2960`) over `--pgdata` and `--waldir` first, collapsing `.`, `..` and repeated or trailing separators. | `canonicalize_path` (`src/port/path.c:337`) is a state machine of its own and is still unported; it is needed in full by the config files NAT-381 writes. It cannot change an absolute path into a relative one, so the `--waldir` absolute-path rule is unaffected, and a link target that differs only in separators resolves to the same directory. | `crates/rinitdb/src/validate.rs` unit test `a_data_directory_path_is_reported_as_it_was_typed`; `crates/rinitdb/tests/t_001_initdb.rs::waldir_becomes_a_pg_wal_symlink` |
| gate | A gate may declare `Scope::StderrAndStatus`, judging only stderr and the exit status; `Scope::Everything` (stdout too) is the default. | A tool ported in chunks has byte-exact *diagnostics* long before it has the *progress output* of the success path — rinitdb's pre-flight errors (NAT-378) against its cluster creation (NAT-379 … NAT-387). Gating the finished half now beats gating nothing. The unjudged stream is still compared and still rendered, and `assert_clean` prints it behind `OUT OF SCOPE (flagged, not silent)`. | `crates/testkit/src/gate.rs` unit tests (`a_narrowed_scope_still_fails_on_stderr_and_on_the_exit_status`, `a_narrowed_scope_forgives_stdout_but_reports_it`, `the_gate_line_says_when_the_verdict_is_narrowed`) |
| rinitdb | The data directory tree is created one entry at a time at an explicit mode (`mkdir` at that mode, then `chmod` to exactly it); C sets one process-wide `umask(pg_mode_mask)` (`initdb.c:3057`) and lets every later `mkdir`/`fopen` inherit it. | `umask` is not reachable from the standard library, the crate is `#![deny(unsafe_code)]` and no libc dependency is approved (AGENTS.md). The end state is identical: `pg_dir_create_mode & ~pg_mode_mask` is `pg_dir_create_mode` and `0666 & ~pg_mode_mask` is `pg_file_create_mode` for both of initdb's two settings. Creating at the mode first means the process umask can only ever make an entry stricter, never laxer, in the window before the `chmod`. | `crates/rinitdb/src/file_perm.rs` unit test `the_mask_never_touches_the_create_modes`; `crates/rinitdb/tests/t_001_initdb.rs::check_pgdata_permissions` and `::check_pgdata_permissions_with_group_access` |
| rinitdb | `-A` never wins over `--auth-local` / `--auth-host`; C's getopt applies whichever switch came last on the command line, so `--auth-host md5 -A trust` leaves `authmethodhost` at `trust` there and at `md5` here. | Same cause as the `--locale` / `--no-locale` entry above: usage-rs reports which switches were given, not where. `-A` before the per-side switches — the spelling upstream's own tests and documentation use — is identical either way. | `crates/rinitdb/src/conf.rs` unit test `a_trailing_dash_a_does_not_win_over_a_per_side_switch` |
| rinitdb | The configuration templates are compiled into the binary (`include_str!` over `crates/rinitdb/share/`); C reads them from `share_path` at run time (`initdb.c:1296`, `:1462`, `:1529`), so `--no-instructions`-style installations can edit them in place. | ADR-0002: a self-contained binary has no `share/` directory to read. The bytes are the vendored PostgreSQL 18.6 files unchanged, so a cluster is identical unless the host's `share/` had been edited — which is exactly the case this port cannot honour. | `crates/rinitdb/src/conf.rs` unit tests `the_embedded_templates_are_the_postgresql_18_6_bytes_we_vendored` (length + digest of each of the three, so a drifted or reformatted template fails rather than shipping) and `every_token_setup_config_replaces_is_present_in_the_template` |
| rinitdb | `BLCKSZ`, `DEF_PGPORT_STR`, `DEFAULT_PGSOCKET_DIR` and the three `DEFAULT_*_FLUSH_AFTER` values are stock-build constants in `pg_config`, not a configure step's answers. | There is no configure step here. A distribution build that chose differently (Debian's `--with-pgsocketdir=/var/run/postgresql`) writes a different `postgresql.conf`; that is a property of that server, and the byte-diff gate against it is what would surface it. | `crates/rinitdb/src/pg_config.rs` unit tests (`the_wal_defaults_are_the_sizes_the_sample_file_documents`, `the_flush_after_table_is_upstreams_in_upstream_order`) |
